# 本地多档案设计

一个浏览器扩展可以管理多份本地文库。每份档案有自己的帖子、媒体、笔记、同步任务、AI 设置和磁盘目录。档案用于分开使用场景或 X 账号，默认只在本机存在。

已实现本地档案创建、切换、改名和存储隔离，以及可选的 X 用户名核对。本项目仅提供 Chrome 扩展。

## 使用流程

- **首次使用**：建立「我的文库」，沿用现有保存位置；新安装从选择文件夹开始。
- **新增档案**：在文库切换菜单点「新建用户文库」，填写名称，并可选填写要绑定的 X 用户名。用户名在创建时写入；无效或已被占用时不会创建。保存目录仍在设置里单独绑定。
- **切换档案**：顶栏和文库页右上角都可以切换用户文库，按钮在文库名旁边显示已绑定的 @用户名，未绑定时显示「未绑定」。切换后，总览、文库、同步、设置及导出都指向该档案。正在采集或发布时提示先结束任务，再切换。即使旧窗口仍开着，旧任务始终写入启动时选定的档案。扩展弹出页用一行显示当前登录的 X 账号：左侧是用户名，右侧用绿色「已绑定」或红色「未绑定」标示本地文件夹。篇数和图片数与上次状态放在停止、刷新按钮下面。弹出页只展示绑定到该账号的文库。
- **改名与换绑定**：切换菜单里点「修改」可改文库名称和绑定的 X 用户名。改名只更新显示，不移动里面的内容，也不切换当前文库。用户名留空则解除绑定；名称无效，或用户名已被占用时，原来的名称和绑定都保持不变。扩展弹出页的「修改」也可以改当前文库的名称和绑定用户名。平时账号行仍是一行，只有打开修改时才多出名称框。换目录影响后续发布，旧目录里的快照可继续打开。
- **删除档案**：切换菜单里可以删除当前没有打开的文库。先点「删除」，再点「确认删除」。确认后，这份文库在这台电脑上的帖子、笔记和目录绑定会去掉。文件夹里已经写好的快照还在。若这份文库仍有进行中的采集，删除会停住并说明，数据保持原样。同步页和弹出页都可以暂停采集。暂停后同一条任务可以继续，也可以结束。弹出页暂停时仍可以刷新点赞页，刷新之后这次采集仍是暂停。同步页暂停时可以点「刷新点赞页」，重新载入当前点赞页，这次采集仍是暂停。若刷新后内容脚本还没接上，同步页会说明可以再点一次「刷新点赞页」，这次采集保持暂停。采集暂停且内容脚本还没接上时，检测说明同样改为再点「刷新点赞页」。暂停时再点「检测状态」，若内容脚本已经接上并且列表可以继续，状态行会说明可以继续，这次采集仍保持暂停。列表还是空的时候，状态行说明脚本已接上、采集仍暂停，检测说明改为再点「刷新点赞页」，继续按钮保持停用。暂停时刷新点赞页之后列表仍是空的，状态行说明列表还是空的、采集仍暂停。已经能看到帖子时，状态行说明可以继续，这次采集仍暂停，继续按钮可以点。当前页不是点赞或收藏页时，状态行说明先打开点赞页，采集仍暂停，继续按钮保持停用。暂停后若点赞页没有响应继续采集，弹出页会说明可以先点刷新，同步页会说明先刷新点赞页，这次采集都保持暂停。采集已暂停时删除会停住，并说明要先结束或继续完成这次采集；暂停不因时间变久而放行。正在打开的文库没有删除按钮。

## 数据边界

| 层 | 设计 |
|---|---|
| 档案注册表 | 本地保存随机 `profileId`、名称、数据库名称和最后使用的档案。档案 ID 与 X 用户名、目录名分离。 |
| 浏览器数据 | 每个档案独立 IndexedDB，帖子 ID 仍为 `x:<数字 ID>`，在档案内去重。媒体、笔记、AI、目录句柄和发布标记都从该档案读取。AI 密钥默认每个档案单独设置，会话密钥按档案保存在内存。 |
| 扩展任务 | 开始时由后台绑定 `profileId + runId + tabId`。后续批次由该记录路由，不读取当时的活动档案。续读检查点和进度按档案及来源页区分，磁盘发布锁按档案区分。 |
| 磁盘目录 | 每个档案使用独立的管理子目录。选择同一上级目录时也各自保存，`catalog.json` 记录 `profileId`，媒体沿用相对路径。 |

## X 账号校验

档案和 X 登录态分别管理。创建档案不会切换 X 登录账号。仅用能从已登录页面明确确认的当前账号做比对，不能用采到的帖子的作者推断。出现账号不符或身份无法确认时，显示当前档案与页面状态，暂停自动入库，等用户核对后再开启。共享 Chrome 环境中的本地档案可用于防串库，同一系统登录下的其他使用者仍可能访问扩展存储和磁盘文件。需要账号或人员间的访问隔离时，应各自使用独立的 Chrome 和系统账户。

在 **设置 → 当前档案** 填写 X 的 `@用户名` 后启用核对。同步开始及每批写入前，只读取 X 导航区的个人资料入口。页面证据缺失、冲突或与绑定不一致时，该批不会入库。已启动的任务同时保留启动时的绑定条件。留空可解除核对。用户名发生变化后需要手动更新绑定；官方归档文件导入仍以用户选定的档案为准。

## 兼容与实施顺序

1. 建立档案注册表和数据库路由，把现有数据库原地登记为默认档案。保留既有正文、媒体、笔记、配置、目录句柄和发布记录。初始化须可重复执行，失败后可再次打开原库。
2. 将任务、断点、配置和文件夹都绑定到档案，再上线新增与切换 UI。切换时清理旧页面的选中项、搜索结果及详情，避免展示上一个档案的缓存。
3. 用两份档案验证同帖独立收录、笔记和设置互不可见、同步期间切换不串库、选择同一个上级目录各自发布，以及旧库升级。账号核对作为独立的可选设置。

**首个验收切片**：创建第二个空档案，切换后看不到原档案资料；分别收录同一条离线样本，各自编辑笔记并发布到不同子目录；切回默认档案后原数据和绑定仍可用。
